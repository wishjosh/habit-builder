# 습관 형성 시스템 · Habit Builder

우리 가족의 작은 실천을 모으는 아이패드용 웹앱입니다.

**앱:** https://wishjosh.github.io/habit-builder/

## 시작하기

1. Safari에서 앱을 열고 첫째 또는 둘째를 고릅니다.
2. 부모 메뉴에서 이름, 할 일, 완료 기준, 반복 방법, 선물 약속을 바꿉니다. 처음 들어 있는 책과 교재는 변경할 수 있는 예시입니다.
3. 실천한 활동의 **다 했어요**를 누릅니다. 다시 누르면 취소합니다.
4. 내 기록에서 주간·월간·활동별 기록을 봅니다. 월간 기록은 인쇄하거나 PDF로 저장할 수 있습니다.
5. Safari의 공유 → **홈 화면에 추가**를 누르면 앱처럼 열 수 있습니다. 기록을 만든 Safari 창과 홈 화면 앱 사이의 저장 공유는 iPadOS 환경에 따라 달라질 수 있으므로 가족 연결을 각각 확인합니다.

매일, 요일 선택, 주간 횟수, 월간 횟수, 특정 날짜의 활동을 지원합니다. 활동 하나는 하루에 한 번 기록하며 별은 중복 적립되지 않습니다. 쉬는 날에는 새 실천 버튼이 잠기고 기존 기록은 남습니다. 선물 사용 후 과거 실천을 취소하면 별 잔액이 음수가 될 수 있습니다. 부모 메뉴에서 선물 사용을 취소하면 돌려받습니다.

## 상위 묶음과 구체적인 할 일

오늘 화면과 부모 메뉴는 **책 읽기 / 수학 / 기타 학습 / 생활 습관 / 몸 움직이기 / 만들고 표현하기**로 묶어 접고 펼칠 수 있습니다. 상위 묶음 아래의 구체 항목에만 완료 버튼과 별이 있습니다.

**부모 메뉴 → 상위 묶음 관리**에서 원하는 묶음을 추가하고 이름·모양·입력 방식을 바꾸거나 삭제할 수 있습니다. 묶음은 두 아이가 함께 사용하며, 할 일과 완료 기록은 아이별로 분리합니다. 책·교재 제목이 필수인 방식과 이름을 선택적으로 적는 방식을 고를 수 있습니다.

묶음을 삭제할 때 남아 있는 두 아이의 할 일은 선택한 다른 묶음으로 옮깁니다. 완료 기록과 별은 유지되며, 지난 기록에는 삭제한 묶음 이름이 남습니다. 이름만 바꾸면 그 묶음의 기록 화면 이름도 함께 바뀝니다. 묶음은 하나 이상 있어야 하므로 마지막 묶음을 삭제하려면 새 묶음을 먼저 만듭니다. 이전 저장본에는 기본 묶음이 자동으로 보충됩니다.

- 책 읽기 → **톰 소여의 모험** → **1~2장 읽기**
- 수학 → **눈높이 수학** → **A1권 1~2쪽 풀기**

각 묶음의 **할 일 추가**에서 책·교재 이름과 할 일·분량을 따로 적습니다. 새 할 일은 ‘정한 날짜에 한 번’이 기본이며 필요하면 반복으로 바꿉니다. 같은 날 두 책을 읽거나 같은 책의 다른 분량을 각각 기록하려면 할 일을 각각 추가합니다. 다음 분량을 만들 때는 새 할 일을 추가하면 기존 분량과 별을 유지할 수 있습니다.

완료하면 **내 기록 → 월간 기록 → 이 달에 읽은 책과 한 일**에 제목별로 모입니다. 책 제목을 펼치면 날짜와 분량을 확인할 수 있습니다. 같은 제목을 여러 번 읽은 기록은 한 목록에 모으되 실천 횟수는 따로 셉니다. 읽기 기록을 완독 권수로 계산하지 않습니다. 다른 판본이나 동명의 책을 구분하려면 제목에 출판사 등을 덧붙입니다.

이전 버전에서 입력한 제목과 기록은 자동으로 바꾸지 않습니다. 기존의 ‘책 읽기’처럼 포괄적으로 적은 할 일은 부모 메뉴의 **수정**에서 책 이름과 구체 분량을 입력하면 됩니다. 완료 당시의 책·교재·묶음은 기록에 보존됩니다. 월간 인쇄 시 접힌 세부 기록도 펼쳐 출력합니다.

## 데이터 저장

화면과 코드는 **GitHub Pages**에서 제공합니다. 가족 기록은 **비공개 Google 스프레드시트**에 저장하며 Apps Script가 읽기·쓰기 통로가 됩니다. Sheets 연결 전에는 이 브라우저에만 저장합니다. 연결 상태는 화면에 표시됩니다. 별도 가족 연결 코드로 각 기기를 연결해야 합니다.

인터넷이 끊겨도 이 기기에 저장하며 다시 연결되면 동기화를 시도합니다. 동시에 여러 기기에서 변경해 충돌하면 자동 덮어쓰기를 중단합니다. 먼저 각 기기의 전체 백업을 받은 뒤, 연결 설정에서 가족 기록을 가져올 수 있습니다. 초기 버전은 두 기기의 충돌 기록을 자동 병합하지 않습니다. 복구 전 로컬 백업을 보관하세요. 브라우저 데이터 삭제·기기 분실에 대비해 전체 기록 백업도 주기적으로 받으세요.

아이 이름·실천 기록·연결 열쇠는 공개 저장소에 포함하지 않습니다. 연결 코드는 기록을 읽고 바꾸는 열쇠이므로 가족만 보관합니다. 부모 메뉴는 설정 화면이며 PIN 보호나 계정별 권한 분리는 아직 없습니다. 일반 백업 파일에는 연결 열쇠가 포함되지 않습니다.

### Google 저장소 만들기

1. 개인 Google 계정의 Apps Script에 새 프로젝트를 만들고 `google/Code.gs`를 붙여넣습니다. 다른 GitHub 계정에서 배포한다면 `APP_ORIGIN`을 해당 Pages 출처로 바꿉니다.
2. `setup`을 한 번 실행하고 Google이 요청하는 스프레드시트 권한을 검토합니다. 비공개 시트가 생성되며 실행 로그에 시트 주소와 가족 열쇠가 표시됩니다. 가족 열쇠를 안전하게 보관합니다. 원문 열쇠는 서버 속성에 저장되지 않으므로 다시 조회할 수 없습니다.
3. 새 배포 → 웹앱 → 실행 사용자 **나**, 액세스 **모든 사용자**로 배포합니다. 웹앱에 접근할 수 있어도 모든 기록 읽기·쓰기는 가족 열쇠 검사를 통과해야 합니다. 시트 자체는 공개하지 않습니다.
4. 앱의 부모 메뉴 → 가족 기록 연결 → 연결 주소와 열쇠 직접 입력에 `/exec` 주소와 가족 열쇠를 넣습니다.
5. 첫 기기를 연결한 다음 **다른 기기 연결**에서 코드를 받아 아이패드에 입력합니다.

시트의 `State`는 앱이 관리하는 저장 원본, `이전 저장`은 직전 저장본입니다. 직접 수정하지 마세요. `실천 기록`, `아이와 활동`은 보기 편하게 만든 표이며 앱에서 저장할 때 갱신됩니다. 시트 표를 수정해도 앱 계획에는 반영되지 않습니다. 기록 수정은 앱의 부모 메뉴를 사용하세요.

## 개발 및 확인

별도 설치 없이 Node.js 22 이상에서 `npm start`로 열고 `npm test`, `npm run check`로 검사합니다. 외부 라이브러리, 광고, 추적 도구를 사용하지 않습니다. 서버 파일은 `google/Code.gs`에 있습니다. GitHub Pages 배포는 main 브랜치의 루트 폴더를 사용합니다.

초기 기능은 iPad 화면 크기에 맞춰 확인합니다. 실제 iPad Safari에서의 터치 조작과 Google 연결은 가정 시험 사용에서 함께 확인할 항목입니다.
