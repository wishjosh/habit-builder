# 습관 형성 시스템 · Habit Builder

우리 가족의 작은 실천을 모으는 아이패드용 웹앱입니다.

**앱:** https://wishjosh.github.io/habit-builder/

현재 버전은 사용자가 정한 **0.4**입니다. 이전 배포 번호의 이력은 [버전 기록](CHANGELOG.md)에 남겨 두며, 다음 번호도 사용자가 정합니다.

## 시작하기

1. 아이를 고르고 **할 일 → 오늘·내일 → 할 일 추가**에서 할 일을 적습니다. 오늘 하나만 정해도 됩니다. **이번 주**에서도 각 날짜의 추가 버튼으로 같은 창을 엽니다.
2. 할 일 이름만으로 충분하면 일기·이불 정리처럼 바로 저장합니다. 책·교재와 분량은 선택 사항입니다. 자주 하는 일은 예시 버튼이나 **전에 정한 일 다시 쓰기**로 내용을 가져옵니다.
3. 반복할 일은 **매일 / 요일을 골라서 / 하루 걸러 격일**을 선택합니다. **시작하는 주만 / 날짜까지 / 종료일 없이 계속** 중 기간을 정합니다. 예를 들어 눈높이는 매일, ORT는 월·수·금으로 따로 정할 수 있습니다.
4. 날짜를 정하기 어려운 일은 **이번 주에 몇 번 · 날짜는 나중에**를 선택합니다. ‘아빠와 책 읽기, 주 2회’는 **이번 주 안에 할 일**에 남습니다. 할 날을 골라도 완료 횟수는 늘지 않습니다. **오늘 했어요**를 누르면 실천과 별을 기록합니다. 한 활동은 하루 한 번 기록하며 주간 횟수는 월요일에 새로 셉니다. 목표를 넘겨 다른 날 추가로 실천할 수도 있습니다.
5. 어느 화면이든 **할 일 제목을 누르면 같은 수정 창**이 열립니다. 오늘·내일 및 전체 목록의 동그란 체크는 완료·완료 취소입니다. 미래의 일은 해당 날짜가 되기 전에는 완료할 수 없습니다. 평가나 소감은 요구하지 않습니다.

이번 주 화면은 월요일부터 일요일까지 7칸을 한 줄에 보여 줍니다. 주제 자체가 할 일인 항목과 세부 할 일 모두 제목만 표시합니다. 성장 주제 설명·예정/완료 문구·완료 버튼은 주간 요약에서 생략합니다. 날짜마다 할 일을 최대 3개까지 요약하고, 넘치는 항목은 **더 보기**나 날짜를 눌러 확인합니다. 긴 제목은 줄여 표시하며 항목을 누르면 전체 내용을 봅니다.

일별·주별 화면은 별개의 계획을 만들지 않습니다. 하나의 할 일을 날짜에 따라 보여 줍니다. **전체 목록**에서는 앞으로 8주의 날짜별 계획, 전체 완료 기록과 최근 4주의 완료 표시 없는 계획, 휴지통을 봅니다. 날짜별·성장 주제별로 바꾸어 볼 수 있습니다. 더 먼 미래와 오래전 날짜는 주간 화살표 또는 날짜 선택으로 확인합니다. 아이 선택에 따라 같은 화면에서 각 아이의 기록을 구분합니다.

## 계획 변경과 실제 기록

반복하는 책이나 분량이 달라지면 **이날만**을 골라 고칩니다. 다른 날은 바뀌지 않습니다. **이날부터 반복 계획**을 고르면 이후 내용·요일·기간을 고칩니다. 날짜를 옮길 때는 ‘이날만’으로 옮깁니다. 이미 한 날은 당시 계획의 사본으로 남습니다. 기존에 따로 바꿔 둔 날짜별 예외는 이후 반복 계획을 바꿔도 유지합니다.

완료한 일을 누르면 **실제로 한 일·분량, 책·교재, 메모**를 고칩니다. 예를 들어 계획은 레슨 1개, 실제는 레슨 2개로 남길 수 있습니다. 별은 중복 적립되지 않습니다. 계획 자체를 잘못 적었다면 **원래 계획을 잘못 적었어요**를 펼쳐 정정하고 이전 계획도 백업의 정정 이력에 보관합니다. **이후 반복 계획 바꾸기**로 앞으로의 계획을 따로 바꿀 수 있습니다.

아이는 새 계획을 만들고 실천을 기록합니다. 기존 계획 변경·삭제와 원래 계획 정정은 부모 공동 확인 표시를 요구합니다. 이 표시는 함께 확인하는 약속이며 PIN이나 계정 권한으로 잠그는 기능은 아닙니다.

**정리하기**에서는 다음 중 하나를 고릅니다.

- **이날의 할 일과 기록 삭제:** 해당 날짜만 목록·기록·별에서 뺍니다. 다른 날짜는 남습니다.
- **이날부터 그만하기:** 앞으로의 반복을 멈추고 이전 기록과 별은 보존합니다.
- **잘못 만든 활동 전체 삭제:** 해당 활동과 기록을 목록·별에서 빼고 휴지통으로 옮깁니다. **전체 목록 → 휴지통 → 되돌리기**로 복원합니다.

휴지통과 원래 계획 정정 이력도 전체 백업과 가족 저장 원본에 포함됩니다. 내려받은 과거 백업과 Google의 이전 저장본은 자동 삭제되지 않습니다. 이미 별을 사용한 뒤 완료 기록을 삭제하면 잔액이 음수가 될 수 있으며 선물 교환 내역은 그대로 남습니다.

## 행동과 성장 주제

새 할 일은 부모가 상위 묶음을 먼저 만들어야만 작성할 수 있는 구조가 아닙니다. 할 일 하나를 적고 성장 주제는 선택해 연결합니다. 기본 주제는 다음과 같습니다.

| 성장 주제 | 아이에게 보이는 이름 | 활동 예시 |
|---|---|---|
| 문해력 | 책과 가까워지기 | 책 읽기, 독서평설 |
| 외국어 | 영어와 친해지기 | 눈높이 영어, ORT |
| 사고력 | 생각하는 힘 기르기 | 눈높이·기탄 수학 |
| 생활 습관 | 내 생활 스스로 하기 | 일기, 이불 정리 |
| 몸과 표현 | 움직이고 표현하기 | 운동, 예체능 |
| 그 밖의 활동 | 새롭게 해 보기 | 아직 분류하지 않은 일 |

**설정 → 성장 주제**에서 추가·이름 수정·순서 변경·삭제를 합니다. 삭제하면 앞으로 할 일을 다른 주제로 옮기며 지난 완료 기록은 원래 주제로 보존합니다. 이전 책 읽기·영어·수학·일기 묶음은 이름과 기존 유형을 바탕으로 주제에 연결합니다. 주제를 바꾸려면 기존 할 일도 새 할 일과 동일하게 항목을 눌러 수정합니다. 이전 분류의 호환 처리는 앱 내부에서 맡습니다. 기존 묶음 일정과 세부 계획은 읽기 호환 방식으로 유지하며 가족 데이터를 일괄 변환하거나 초기화하지 않습니다.

## 성취와 기록

**내 기록**은 계획 목록을 다시 관리하는 곳이 아니라 쌓인 실천을 주간·월간·성장 주제와 책·활동별로 돌아보는 곳입니다. 여기서도 항목을 누르면 같은 창에서 실제 내용을 고칩니다. 책을 여러 날 읽은 횟수를 완독 권수로 계산하지 않습니다. 소감은 선택 사항이며 월간 기록을 인쇄하거나 PDF로 보관할 수 있습니다.

새 할 일은 하루 한 번 완료할 때 별 1개를 받습니다. 기존 항목의 별 설정과 교환 내역은 유지합니다. **별 모으기**에서 모은 별을 확인하고, **설정 → 우리 가족의 선물**에서 가족이 정한 목록을 관리합니다.

**설정 → 함께하는 아이들**에서 아이 이름과 12간지 캐릭터를 고릅니다. **기록 보관하기**에서는 전체 JSON 백업과 계획·실제·성장 주제를 담은 실천 기록 CSV를 내려받습니다. Google 읽기용 표의 기존 열 구성은 유지되며 추가 정보 전체는 저장 원본과 JSON 백업에 있습니다.

Safari의 공유 → **홈 화면에 추가**로 앱처럼 열 수 있습니다. 새 개편을 적용할 때 연결한 기기마다 페이지를 다시 열어 최신 화면을 사용하세요. 이전 앱이 열린 채로 있으면 새 저장 형식을 읽지 못할 수 있습니다.

## 데이터 저장

화면과 코드는 **GitHub Pages**에서 제공합니다. 가족 기록은 **비공개 Google 스프레드시트**에 저장하며 Apps Script가 읽기·쓰기 통로가 됩니다. Sheets 연결 전에는 이 브라우저에만 저장합니다. 연결 상태는 화면에 표시됩니다. 별도 가족 연결 코드로 각 기기를 연결해야 합니다.

인터넷이 끊겨도 이 기기에 저장하며 다시 연결되면 동기화를 시도합니다. 동시에 여러 기기에서 변경해 충돌하면 자동 덮어쓰기를 중단합니다. 먼저 각 기기의 전체 백업을 받은 뒤, 연결 설정에서 가족 기록을 가져올 수 있습니다. 초기 버전은 두 기기의 충돌 기록을 자동 병합하지 않습니다. 복구 전 로컬 백업을 보관하세요. 브라우저 데이터 삭제·기기 분실에 대비해 전체 기록 백업도 주기적으로 받으세요.

아이 이름·실천 기록·연결 열쇠는 공개 저장소에 포함하지 않습니다. 연결 코드는 기록을 읽고 바꾸는 열쇠이므로 가족만 보관합니다. 설정 화면에는 PIN 보호나 계정별 권한 분리가 아직 없습니다. 일반 백업 파일에는 연결 열쇠가 포함되지 않습니다.

### Google 저장소 만들기

1. 개인 Google 계정의 Apps Script에 새 프로젝트를 만들고 `google/Code.gs`를 붙여넣습니다. 다른 GitHub 계정에서 배포한다면 `APP_ORIGIN`을 해당 Pages 출처로 바꿉니다.
2. `setup`을 한 번 실행하고 Google이 요청하는 스프레드시트 권한을 검토합니다. 비공개 시트가 생성되며 실행 로그에 시트 주소와 가족 열쇠가 표시됩니다. 가족 열쇠를 안전하게 보관합니다. 원문 열쇠는 서버 속성에 저장되지 않으므로 다시 조회할 수 없습니다.
3. 새 배포 → 웹앱 → 실행 사용자 **나**, 액세스 **모든 사용자**로 배포합니다. 웹앱에 접근할 수 있어도 모든 기록 읽기·쓰기는 가족 열쇠 검사를 통과해야 합니다. 시트 자체는 공개하지 않습니다.
4. 앱의 설정 → 가족 기록 연결 → 연결 주소와 열쇠 직접 입력에 `/exec` 주소와 가족 열쇠를 넣습니다.
5. 첫 기기를 연결한 다음 **다른 기기 연결**에서 코드를 받아 아이패드에 입력합니다.

시트의 `State`는 앱이 관리하는 저장 원본, `이전 저장`은 직전 저장본입니다. 직접 수정하지 마세요. `실천 기록`, `아이와 활동`은 보기 편하게 만든 표이며 앱에서 저장할 때 갱신됩니다. 가족의 기존 저장 웹앱도 버전 2로 갱신해, 다음 기록 저장부터 `실천 기록` 표에 계획과 실제 내용이 별도 열로 표시됩니다. 시트 표를 수정해도 앱 계획에는 반영되지 않습니다. 실제 내용은 앱의 오늘 화면이나 내 기록에서 수정하세요.

## 개발 및 확인

별도 설치 없이 Node.js 22 이상에서 `npm start`로 열고 `npm test`, `npm run check`로 검사합니다. 외부 라이브러리, 광고, 추적 도구를 사용하지 않습니다. 서버 파일은 `google/Code.gs`에 있습니다. GitHub Pages 배포는 main 브랜치의 루트 폴더를 사용합니다.

초기 기능은 iPad 화면 크기에 맞춰 확인합니다. 실제 iPad Safari에서의 터치 조작과 Google 연결은 가정 시험 사용에서 함께 확인할 항목입니다.
